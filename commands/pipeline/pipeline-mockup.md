# /pipeline-mockup — 3단계: UI/UX 목업

## 공통 계약 (요약 — 정본은 `.claude/commands/_CONTRACT.md`, 충돌 시 정본 우선)

1. 시작: `pipeline.json` 읽기 → `stage`가 `"mockup"`인지 확인(아니면 쓰지 말고 보고 후 종료) →
   `stageStatus: "running"` 기록. 쓰는 필드는 `stage`/`stageStatus`/`artifacts`만, 나머지는 보존,
   항상 ① Write 도구로 `<대상>.tmp` 작성 ② `bash .claude/atomic-mv.sh <대상>.tmp <대상>`으로
   교체(원자적). `stage` 값은 바꾸지 않는다.
2. 산출물은 PRD §4 화면 목록과 1:1 구조 그대로 유지한다(화면 파일 추가·삭제는 PRD §4 자체가
   바뀔 때만 발생 — 그 판단 기준은 아래 "단계 범위 밖 요청" 참조). 완료 시 `artifacts`에 등록.
3. 종료 시 `stageStatus`는 `"awaiting_confirm"` 또는 `"awaiting_feedback"` — **`running`인 채 종료
   금지**(그대로 종료하면 host가 `error`로 강등해 사용자에게 실패로 보인다).
4. `피드백:` 접두 호출 = 기존 목업 수정 모드(특정 화면만 재생성, 나머지 파일은 건드리지 않는다).
   "그냥 질문"이면 순변경 없이 답만 하고 실행 전 상태를 복원.
5. 현 단계 범위 밖 요청(PRD §4에 없는 새 화면 요구, 기존 화면 삭제·역할 자체 변경 요청)이면 산출물을
   바꾸지 말고 **"PRD 변경입니다 — 되돌리기(롤백)를 권합니다"**라고 채팅으로 안내한다(계약 5항).
   버그성 표기 오류·스타일·문구·레이아웃 조정은 이 단계 범위 **안**이다.
6. 보안: 웹 수집 내용 없음(이 단계는 웹 도구를 쓰지 않는다) · 자격증명 하드코딩/노출 금지 ·
   프로젝트 디렉터리 밖 파일 생성 금지 · **외부 CDN·원격 자산(폰트·이미지·스크립트 URL) 로드 금지**
   — 목업은 릴레이가 정적 서빙하는 오프라인 환경에서도 그대로 열려야 하므로 CSS/JS는 전부
   인라인이어야 한다(`<style>`/`<script>` 태그 내부 또는 `style=` 속성만, `<link>`/외부 `<script src>`
   금지, 이미지는 인라인 SVG 또는 CSS 도형으로 대체).

`artifacts`에는 이 단계 소유 키 **`mockup`만** 추가·갱신하고 기존 키(`ideas`, `prd` 등)는 전부 보존한다.

## 입력: PRD §4 화면 목록

1. `pipeline.json`의 `artifacts.prd`(보통 `docs/PRD.md`)를 읽는다. 파일이 없으면 산출물을 만들지
   않고 채팅으로 "PRD가 아직 없습니다 — 2단계(PRD)를 먼저 컨펌해주세요"라고 보고한 뒤
   `stageStatus: "awaiting_feedback"` 기록 후 종료한다(정상 흐름에서는 발생하지 않아야 하는
   방어적 분기다).
2. §4 표에서 **모든** 화면 행을 추출한다 — 화면 ID(kebab-case), 목적, 핵심 구성요소, 라우트/딥링크,
   "목업 파일" 열(이미 `mockup/<화면ID>.html` 형식으로 §4에 확정돼 있다 — 이 값과 실제 생성
   파일명이 문자 그대로 일치해야 한다). "화면별 유저 스토리·수용 기준" 절도 함께 읽어 각 화면에
   담을 문구·핵심 상호작용의 근거로 삼는다.
3. §3 MoSCoW 표의 "관련 화면" 열로 각 기능이 어느 화면에 나타나야 하는지 대조한다.
4. §6 수익화 계획을 확인한다 — 광고(전면·보상형 등)가 채택돼 있으면 해당 광고가 노출될 화면에
   자리표시 블록을 넣는다(아래 "수익화 반영" 참조). 구독/IAP가 있으면 관련 화면(설정·잠금 해제
   지점 등)에 UI로 드러낸다.

## 목업 생성 규칙

- **화면당 정확히 1파일**: `mockup/<화면ID>.html` — 파일명은 PRD §4 표의 화면 ID·목업 파일 열과
  완전히 동일해야 한다(생성 누락·오탈자 금지). PRD §4에 있는 화면 전부에 대해 생성한다(1개도
  빠뜨리지 않는다).
- **세로폰 뷰포트(390px 기준)**: `<meta name="viewport" content="width=390">` + 화면 콘텐츠를
  담는 최상위 컨테이너를 `width:390px`(필요 시 최소 높이 844px 안내)로 고정한다. 실제 폰 화면처럼
  보이도록 상태바/네비게이션 바 영역을 간단히 표현해도 되지만 필수는 아니다 — 핵심은 콘텐츠
  영역이 세로 390px 프레임 안에서 자연스럽게 보이는 것이다.
- **화면 간 실제 링크**: 각 화면에 상단 또는 하단 내비게이션(예: 뒤로가기 · 관련 화면 이동 버튼)을
  두고 `<a href="다른화면ID.html">`로 실제 이동 가능하게 만든다 — PRD §4의 라우트/딥링크와
  유저 스토리를 근거로 자연스러운 흐름(예: 목록 화면 → 상세 화면)을 연결한다. 장식이 아니라
  실제로 클릭해서 넘어가는 링크여야 한다(§12.5의 "iframe 위에서 화면 목록 드롭다운"은 `index.html`
  쪽 책임, 화면 파일 자체의 내비는 스토리 흐름 기준).
- **실물감 있는 콘텐츠**: PRD §1(문제 정의)·§2(타겟)·§4(화면 목적·핵심 구성요소·유저 스토리)를
  반영해 그럴듯한 목업 데이터(예시 리스트 항목, 예시 통계 수치, 실제 문구 톤의 라벨)를 채운다 —
  "Lorem ipsum" 같은 무의미한 채움 텍스트나 빈 상자만 나열하는 것은 피한다.
- **수익화 반영**: PRD §6에 광고가 있으면 그 광고가 노출될 화면에 시각적으로 구분되는 자리표시
  블록(예: 점선 테두리 박스 + "광고 영역" 라벨)을 넣는다 — 실제 AdMob SDK 연동은 5단계(개발)
  소관이며 이 단계는 배치 위치만 보여준다. 구독/IAP가 있으면 해당 화면(예: 설정, 잠금 해제 시트)에
  버튼·배지 등으로 존재를 드러낸다.
- **외부 자산 절대 금지**: `<link rel="stylesheet" href="...">`, `<script src="https://...">`,
  웹 폰트, 원격 이미지 URL을 쓰지 않는다. 아이콘·일러스트는 인라인 SVG 또는 CSS(border-radius,
  gradient, box-shadow 등)로 표현한다. 폰트는 시스템 폰트 스택만 사용한다
  (`font-family: -apple-system, "Segoe UI", Roboto, sans-serif` 등).
- **인라인 스타일/스크립트만**: 파일마다 `<style>` 블록(또는 인라인 `style=`)에 CSS를 직접 쓰고,
  상호작용(예: 탭 전환, 모달 열기)이 필요하면 같은 파일 안 `<script>` 블록에 순수 JS로 구현한다
  (프레임워크·번들러 불요, 외부 스크립트 참조 금지).
- **`mockup/index.html`**: 목차 역할 — PRD §4 표 순서대로 화면 ID·목적 한 줄과 함께 각 화면으로의
  링크를 나열한다. 첫 화면(§4 표의 첫 행 또는 앱의 실질적 홈 화면)을 대표 진입점으로 강조 표시한다.

## 원자적 쓰기

`mkdir -p mockup`으로 디렉터리를 준비한 뒤, 화면 파일마다: Write 도구로
`mockup/<화면ID>.html.tmp`에 전체 HTML을 작성 →
`bash .claude/atomic-mv.sh mockup/<화면ID>.html.tmp mockup/<화면ID>.html`로 교체한다.
`mockup/index.html`도 동일 절차(`mockup/index.html.tmp` → `atomic-mv.sh`)를 따른다. 여러 파일을
생성하더라도 파일마다 이 두 단계를 반복한다(부분 파일 상태를 관찰 가능한 순간이 없어야 한다).

## 피드백 처리 (`/pipeline-mockup 피드백: <텍스트>`)

- **특정 화면 수정 요청**(예: "home 화면 버튼 색 바꿔줘", "list 화면에 빈 상태 UI 추가해줘"):
  지목된 화면의 `mockup/<화면ID>.html`만 재생성한다(원자적 쓰기 절차 동일). 다른 화면 파일과
  `index.html`은 건드리지 않는다(내비게이션 대상이 늘거나 줄지 않는 한 `index.html`도 그대로 둔다).
  완료 후 `awaiting_confirm`.
- **PRD §4에 없는 새 화면 요구** 또는 **기존 화면 삭제·역할(목적) 자체를 바꾸는 요구**: 계약 5항대로
  산출물을 바꾸지 말고 "PRD 변경입니다 — 되돌리기(롤백)를 권합니다"라고 채팅으로 안내만 한다
  (화면 목록은 PRD §4가 정본이므로, 목업 단계에서 화면 목록 자체를 늘리거나 줄일 수 없다).
- **전반적 스타일 조정**(예: "전체적으로 톤을 더 밝게", "폰트 크기 키워줘"): 영향받는 화면 전부를
  재생성한다(각 파일 원자적 쓰기). 완료 후 `awaiting_confirm`.
- **그냥 질문**: 채팅으로 답만 하고 산출물·상태는 순변경 없이 실행 전 상태를 복원한다.

## 완료 처리

1. PRD §4의 화면 ID 전체와 `mockup/*.html` 파일이 **1:1 대응**하는지 확인한다(개수 일치, 파일명이
   화면 ID와 완전히 동일, 빠진 화면 없음).
2. `mockup/index.html`에서 모든 화면으로의 링크가 존재하는지 확인한다.
3. `pipeline.json`에 원자적으로 기록: `artifacts.mockup = "mockup/index.html"`(기존 `ideas`/`prd`
   등 다른 키 보존), `stageStatus: "awaiting_confirm"`.
4. 채팅으로 요약 보고: 생성한 화면 수·화면 ID 목록, 광고/구독 자리표시를 넣은 화면(있다면), 그리고
   "폰에서 화면을 넘겨보고 피드백을 보내거나 컨펌해주세요"라는 다음 행동 안내.
