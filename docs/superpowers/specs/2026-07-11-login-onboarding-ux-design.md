# ID/비밀번호 로그인 + 시작 설정 UI + 폰 UX 개선 — 설계

날짜: 2026-07-11 · 상태: 사용자 리뷰 대기 · 짝 스펙: `2026-07-11-custom-pipeline-templates-design.md`(템플릿·알림 — 이 문서가 참조)

## 0. 목표

여섯 가지 사용자 불편을 푼다:

1. **로그인 간소화** — 코드+비밀번호 2개 암기 → 사용자가 직접 정한 **ID + 비밀번호** 하나의 로그인 폼.
2. **자동 로그인** — 브라우저를 나갔다 와도 재로그인 없이 자동 재접속.
3. **시작 설정 UI** — `npm start` 첫 실행 시 PC 브라우저에 설정 페이지가 떠서 ID/비밀번호를 직접 만들고, 파이프라인 템플릿·산출물 md 템플릿·알림까지 한 화면에서 커스텀.
4. **산출물 md 폰 편집** — 아이디어/PRD 등 산출물 문서를 폰 뷰어에서 직접 수정·저장.
5. **컴팩트 진행률** — 진행률+단계 카드가 채팅 시야를 절반 가까이 먹는 문제(스크린샷 확인) → 접이식 한 줄 헤더.
6. **쉬운 말 규칙** — 산출물·채팅 보고의 내부 용어("카드", "slug", "모드 A/B" 등)를 일반 사용자 눈높이로 풀어 쓰게 강제.

## 1. ID/비밀번호 로그인

### 1.1 현행 → 변경

- 현행: 폰이 `?code=<6자리>&secret=<비밀번호>`로 WS 접속. 코드는 실행마다 바뀜 — 사용자가 늘 2개를 옮겨 적어야 한다.
- 변경: 폰 로그인 폼은 **ID + 비밀번호** 2칸. 코드는 사용자에게서 완전히 사라진다(호스트↔릴레이 내부 세션 키·reconnectKey 메커니즘은 무변경 — 폰 조회 경로만 바뀜).
- `npm start` 릴레이에는 호스트가 1개뿐이므로, 릴레이는 ID+비밀번호가 맞으면 **유일한 활성 호스트 세션**에 폰을 붙인다. (검증 실패 시 기존과 동일하게 401 종료.) 재연결 유예로 세션이 일시적으로 2개 이상이면 **host 소켓이 살아있는 최신 세션**을 택한다.

### 1.2 자격증명 저장 — `.relay-auth.json`

```json
{ "id": "testuser", "password": "example-password" }
```

- 위치: cwd 루트, `.gitignore` 대상. 평문 저장 — 기존 `.relay-password`와 동일한 로컬 파일 신뢰 모델(변경 없음, §7 보안 노트에 명시).
- 결정 우선순위(기존 규칙 확장): `RELAY_ID`/`RELAY_PASSWORD` 환경변수 > `.relay-auth.json` > **(없으면 설정 UI로 유도 — §3)**.
- 검증 규칙: ID는 영문 소문자·숫자 3자 이상, 비밀번호 4자 이상(현행 규칙 유지).
- 마이그레이션: `.relay-auth.json`이 없고 `.relay-password`만 있으면 → ID 미설정 상태로 간주하고 설정 UI로 유도. 설정 완료 시 `.relay-auth.json`으로 통합(기존 비밀번호를 기본값으로 프리필). `npm run set-password`는 `.relay-auth.json`의 password 필드를 갱신하는 것으로 재지정.
- 터미널 공유 카드 갱신: `코드` 줄 삭제, `아이디` 줄 추가. 공유 링크의 `#code=` 프래그먼트는 `#id=<아이디>`로 대체(프리필용 — 비밀번호는 절대 링크에 넣지 않는다).

## 2. 자동 로그인

- 로그인 성공 시 릴레이가 `paired` 메시지에 **`phoneToken`**(세션별 고엔트로피 랜덤, previewToken과 별개)을 담아 회신 → 폰이 `localStorage`(origin 키)에 `{ id, phoneToken }` 저장. 비밀번호는 저장하지 않는다.
- 페이지 재방문/새로고침 시: 저장된 phoneToken이 있으면 `?id=&phoneToken=`으로 자동 접속 — 성공하면 로그인 화면을 건너뛰고 바로 홈. 실패(세션 소멸·토큰 불일치)하면 토큰을 지우고 로그인 폼으로(ID는 프리필).
- WS 순단 재연결(기존 폰 재연결 흐름)도 같은 토큰 경로를 쓴다 — 현행 "페어링 화면 복귀" 대신 조용한 자동 재접속, 실패 시에만 로그인 폼.
- **한계(명시)**: `localStorage`는 origin 단위인데 trycloudflare 터널 주소는 재시작마다 바뀐다 → **PC에서 npm start를 다시 하면 새 주소에서 최초 1회 로그인은 필요**하다. 같은 실행 안에서는(브라우저 이탈·탭 종료·재방문 포함) 항상 자동 로그인. 고정 도메인 지원은 범위 밖.

## 3. 시작 설정 UI (온보딩 + 상시 관리 페이지)

### 3.1 동작

- `npm start` 시 `.relay-auth.json`이 없으면(첫 실행): 터미널에 안내를 찍고 **PC 기본 브라우저로 `http://localhost:<port>/setup?k=<관리키>` 자동 오픈**(macOS `open`/Windows `start`/Linux `xdg-open`). ID/비밀번호를 만들기 전까지 폰 접속은 거부된다.
- 이후 실행: 설정이 있으면 바로 기존 시작(공유 카드 출력). 터미널 카드에 `관리 페이지: http://localhost:<port>/setup?k=<관리키>` 한 줄을 추가해 언제든 다시 열 수 있게 한다.
- 계정 저장이 끝나면 설정 페이지가 **접속 카드**(폰 접속 링크 + QR 코드)를 표시한다 — 폰 카메라로 스캔하면 ID 프리필 로그인 폼이 열린다. QR 생성은 `qrcode` npm 패키지(서버 사이드, data URI)로 — 신규 의존성 1개.

### 3.2 탭 구성

| 탭 | 내용 | 백엔드 |
|---|---|---|
| **계정** | ID/비밀번호 생성·변경 | `.relay-auth.json` 원자적 쓰기 |
| **파이프라인 템플릿** | 짝 스펙의 템플릿 기능 전부(목록·복제·스텝 편집·프롬프트 편집) — 폰 UI와 동일 기능의 데스크톱 뷰 | `template-store` 재사용 |
| **산출물 템플릿** | `templates/*.template.md`·`proposal.template.html` 등 산출물 서식 파일 편집기(파일 목록 + 텍스트 에디터 + 기본값 복원) | §3.3 |
| **알림** | ntfy 토글·토픽 표시·테스트 발송(짝 스펙 §5와 동일 설정 파일) | `notify` 재사용 |

### 3.3 산출물 템플릿 편집

- 대상: `templates/` 바로 아래 파일(`PRD.template.md`, `IDEAS.template.md`, `ESTIMATE.template.md`, `RELEASE.template.md`, `proposal.template.html`, `COST-GUARDRAILS.md`). `flutter-starter/`·스키마 json은 편집 대상에서 제외(깨지기 쉬움 — 범위 밖).
- 최초 수정 시 원본을 `templates/.orig/<파일명>`으로 백업 → [기본값 복원]이 이 백업에서 되살린다. 편집본은 이후 새로 만드는 모든 프로젝트에 시드된다(기존 프로젝트 무영향 — 시드 스냅샷 원칙 동일).
- 저장 시 검증: md 템플릿은 섹션 헤더(`## §N`) 존재 여부만 가볍게 확인하고, 깨져 보이면 경고 후 저장은 허용(사용자 소유 파일).

### 3.4 관리 API와 공유 모듈

- 설정 페이지는 릴레이가 서빙하는 정적 페이지 + `POST/GET /setup/api/*` JSON 엔드포인트.
- 접근 제어: **① 요청 원격 주소가 loopback인 경우만 + ② `k=<관리키>` 일치**(관리키는 실행마다 랜덤 생성, 터미널에만 출력). 둘 다 만족해야 응답 — 같은 PC의 다른 사용자·탭내 CSRF를 차단한다.
- 짝 스펙에서 `src/cli/template-store.ts`로 계획한 모듈은 릴레이도 쓰므로 **`src/shared/template-store.ts`로 위치 변경**(짝 스펙 §4.2 정정). notify 설정 읽기/쓰기도 같은 이유로 `src/shared/notify-store.ts`로 분리(발송 로직은 cli에 남음).
- 관리 API로 자격증명이 바뀌면: 릴레이는 다음 로그인부터 새 값 적용, 기존 폰 세션은 유지(끊지 않음 — 단순성).

## 4. 산출물 md 폰 편집

- 폰 산출물 뷰어(현행 `artifact_get` 렌더링)에 **[✏️ 직접 수정]** 버튼 추가 → 전체화면 textarea(원문 md) + [저장]/[취소].
- 신규 메시지: 폰→PC `artifact_set { project, key, content }` / PC→폰은 기존 `artifact`(저장 후 갱신본 회신)와 `log`(거부 사유).
- host 처리 규칙:
  - 경로 검증은 기존 `artifact_get`과 동일(artifacts에 등록된 `.md` 키만, 프로젝트 디렉터리 탈출 차단).
  - **스킬 실행 중(`running`)이면 거부** — "작업이 끝난 뒤 수정해 주세요" log 회신(쓰기 충돌 방지).
  - 저장은 tmp+rename 원자적 쓰기. 저장 후 채팅 로그에 `📝 사용자가 <문서명>을 직접 수정했어요` 한 줄을 남긴다 — 다음 `피드백:` 실행 시 Claude가 파일을 다시 읽으므로 수정본 기준으로 이어진다(스킬은 산출물을 항상 파일에서 읽는다 — 추가 계약 변경 불필요).
  - 크기 상한 1MB(비정상 페이로드 차단).
- 컨펌 흐름 무변경: 수정 후에도 [컨펌] 버튼으로 다음 단계 진행.

## 5. 컴팩트 진행률 UI

스크린샷 기준 문제: 단계 pill 줄 + 진행 카드(제목·설명·컨펌 비활성 버튼·중단 버튼)가 화면 상단 ~40%를 차지.

- **접힘(기본)**: 상단 고정 한 줄 — `[진행바] 2/7 PRD · 진행 중 ▾`. 높이 목표 44px 이하.
- **액션이 필요할 때만 버튼 노출**: `awaiting_confirm`이면 접힘 상태에도 [✓ 컨펌] 버튼이 그 줄에 인라인 표시(현행 "컨펌 (단계가 끝나면 활성화)" 상시 비활성 버튼 삭제). `awaiting_feedback`/`error`는 줄 색·아이콘으로 표시.
- **펼침(탭)**: 기존 카드 내용 전부 — 단계 pill(롤백 탭), 상태 설명, [■ 중단], 산출물 열기. 다시 탭하면 접힘. 상태 전이 시 자동으로 펼치지 않는다(시야 보존 — 접힘 줄 색 변화 + 기존 인앱 알림으로 충분).
- 접힘/펼침 상태는 프로젝트별 localStorage 기억.

## 6. 쉬운 말 규칙 (산출물·채팅 보고)

- `_CONTRACT.md`에 **7항** 신설: "사용자 대면 텍스트(채팅 보고·산출물 본문)는 비개발자 눈높이로 쓴다 — ① 내부 용어(카드, slug, 모드 A/B, MoSCoW, kebab-case 등)는 화면에 그대로 쓰지 말고 풀어 쓰거나 첫 등장에 괄호 한 줄 풀이를 붙인다 ② 표·지표에는 그 숫자가 뭘 뜻하는지 한 줄 설명을 단다 ③ 영어 축약어는 한국어 설명을 우선한다."
- 각 builtin 스킬의 "채팅 보고" 형식 문구에 같은 요구 반영(ideation의 "실행 정보" 표처럼 감사 로그성 숫자는 **산출물에서 접거나 '자세히' 섹션으로 이동**).
- 짝 스펙의 `_GENERIC_STEP.md` 스켈레톤에도 동일 조항 포함.
- 산출물 템플릿(`IDEAS.template.md` 등)의 표 헤더에 풀이 행 추가는 §3.3 편집기로 사용자가 직접 조정할 수도 있다(기본 템플릿 자체도 이 규칙으로 한 차례 손본다).

## 8. 보안 노트

- 비밀번호는 여전히 평문 로컬 파일(기존 `.relay-password` 모델 유지) — 파일 권한 0600으로 기록. 해시 저장은 릴레이·CLI 양쪽 검증 구조상 이득이 작아 범위 밖(로컬 단일 사용자 파일).
- `phoneToken`은 세션 수명(릴레이 프로세스) 한정 — 유출돼도 재시작이면 무효. 링크·로그에 비밀번호를 넣지 않는 원칙 유지(`#id=`만 허용).
- `/setup`은 loopback + 실행별 랜덤 관리키 이중 게이트. 터널을 통해서는 절대 도달 불가(원격 주소 검사).
- `artifact_set`은 등록된 md 키만·경로 탈출 차단·실행 중 거부·1MB 상한.
- ID는 비밀이 아니다(공유 링크에 포함) — 인증은 비밀번호+(재접속 시) phoneToken이 담당.

## 9. 에러 처리

- 자동 로그인 실패(토큰 만료 등) → 토큰 폐기 후 로그인 폼(ID 프리필), 에러 토스트 없이 조용히.
- 설정 전 폰 접속 시도 → "PC에서 초기 설정을 먼저 완료해 주세요" 오류 회신.
- 브라우저 자동 오픈 실패(headless 등) → 터미널에 URL만 출력하고 계속 진행.
- 산출물 저장 충돌(실행 중) → 거부 + 사유, 폰은 편집 내용을 잃지 않게 textarea 유지.
- `templates/.orig/` 백업 실패 시 편집 저장도 중단(복원 불가 상태 방지).

## 10. 테스트

- **auth-store**: 생성/검증/마이그레이션(`.relay-password`→`.relay-auth.json`)/env 우선순위.
- **relay**: id+pw 로그인 성공·실패, phoneToken 재접속, 설정 전 접속 거부, `/setup` 게이트(비-loopback·키 불일치 401), 자격증명 변경 후 신규 로그인 반영.
- **pipeline-manager**: `artifact_set` 정상 저장·실행 중 거부·경로 탈출 거부·채팅 로그 기록.
- **template/산출물 템플릿 API**: 편집·복원·백업 실패 시 중단.
- **web 수동 인수**(ACCEPTANCE 추가): 첫 실행 온보딩→QR 접속→자동 로그인→md 편집→컴팩트 헤더 시나리오.

## 11. 범위 밖

고정 도메인(재시작 간 자동 로그인), 다중 사용자 계정, 비밀번호 해시화, md 실시간 공동 편집(동시 편집 병합), 웹푸시, 설정 페이지의 원격(터널) 접근.
