왜 섹션이 고정인가 — 다음 단계 스킬들이 기계적으로 읽어야 하기 때문. 화면 목록이 없으면 목업이, 데이터 모델이 없으면 개발이 설 곳이 없음
화면 ID가 관통 키 — §4의 ID가 목업 파일명 → Flutter 라우트 → 스토어 스크린샷까지 그대로 이어짐
백엔드 결정은 여기서 예고 — §5·§6이 4단계 산정(비용 리스크 표)의 입력이 됨

§1

문제 정의

소비: 전 단계의 판단 기준

습관 앱은 많지만 대부분 기록이 "숙제"처럼 무겁다 — 가입 요구, 과한 설정, 느린 첫 화면. 그래서 3일 쓰고 지운다. 이 앱은 열자마자 체크 한 번이 전부인 최소 마찰 습관 트래커다. 로그인 없음, 서버 없음, 오프라인 완전 동작.

템플릿 규칙 — 3~5문장. "무엇을 안 만들 것인가"가 드러나야 함. 여기 적힌 원칙이 이후 모든 기능 논쟁의 심판.
§2

타겟 사용자

소비: 릴리즈(스토어 문구 톤)
주 타겟 — "작심삼일 반복자" (25–39)새해·월초마다 습관 앱을 설치하고 며칠 만에 이탈한 경험 2회 이상. 복잡한 기능보다 "끊기지 않는 기분(스트릭)"이 동기.
부 타겟 — "미니멀 기록가"노션·수첩에 수동 기록 중. 광고에 관대하지 않으므로 광고 빈도 설계에 반영(§6).
