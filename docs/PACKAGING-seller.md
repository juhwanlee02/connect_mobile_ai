# 판매자용 패키징 및 판매 가이드

## 1. 개요: 모델 A란?

**모델 A = 고객 PC에서 전부 실행.**

릴레이 서버, Claude Code 실행, 미리보기 서빙이 모두 고객의 PC에서 이루어집니다. 판매자(운영자)가 별도로 운영할 서버가 없으므로 **운영자 인프라 비용 0원**입니다.

### 구매 전 체험 (try-before-buy) 판매 구조

이 도구는 **라이선스 키 없이도** 체험판으로 바로 실행됩니다.

- **체험판 (키 없음):** 프로젝트 1개까지 무료로 사용 가능. 폰 화면에 🧪 체험판 배너가 표시되고, 두 번째 프로젝트 생성 시 구매 안내 메시지가 나타납니다.
- **정품 (키 있음):** 멀티프로젝트 + 병렬 실행 무제한. 폰에 ✅ 정품 상태가 표시됩니다.

고객이 키 없이 먼저 도구를 체험하고, 더 필요해지면 구매하는 자연스러운 흐름을 만들 수 있습니다. 배포본을 전달할 때 라이선스 키가 없어도 됩니다 — 구매 후 키를 별도 전달하면 됩니다.

> **솔직한 한계:** 체험판 제한은 오프라인/로컬에서 동작합니다. 기술적으로 우회가 불가능하지는 않으나, 일반 사용자에게는 충분한 구매 유도 장치로 작동합니다. 강력한 복제 방지가 필요하다면 서버 검증 방식(모델 B)이 필요합니다.

### 제품 특징 (판매 포인트)

- **체험 후 구매:** 키 없이 체험판(프로젝트 1개)으로 먼저 사용해보고, 구매 후 키를 등록하면 멀티프로젝트가 무제한으로 열립니다.
- **멀티 프로젝트 (정품 전용):** 고객이 여러 프로젝트를 동시에 관리하고 병렬로 빌드할 수 있습니다. 각 프로젝트는 `projects/<이름>/public/`에 독립적으로 저장되며, 릴레이가 `/preview/<이름>/`으로 서빙합니다.
- **크로스 플랫폼:** macOS / Windows / Linux 모두 지원 (Node.js 기반, `cross-spawn` 사용).
- **더블클릭 런처:** `launchers/` 폴더에 OS별 런처(`시작.command`, `시작.bat`, `시작.sh`)가 포함됩니다. 체험판은 런처를 더블클릭하기만 하면 되고, 구매 후에는 `license.txt`에 키를 한 번 붙여넣으면 이후 런처 더블클릭만으로 정품이 실행됩니다.

### 한계

- 미리보기는 고객이 PC에서 프로그램을 켜두는 동안에만 유지됩니다.
- 터널 URL은 영구적이지 않습니다. 실행할 때마다 새로운 URL이 생성됩니다.
- 완전한 SaaS 형태(영구 URL, 서버 호스팅, 구독 결제)를 원하면 **모델 B**가 필요합니다(6절 참고).

## 2. 라이선스 발급

고객에게 나누어줄 라이선스 키는 아래 명령으로 발급합니다.

```bash
# N개 발급 (예: 5개)
npm run gen-license 5
```

실행하면 `CPMC-XXXXXX-YY` 형식의 키가 N개 출력됩니다. **1인 1키** 원칙으로 각 고객에게 별도의 키를 전달하세요.

### 솔직한 한계와 권장 조치

> **오프라인 검증 방식**이므로 키 알고리즘을 분석하면 이론적으로 위조가 가능합니다. 결정적인 복제는 막지 못합니다. 마찬가지로 체험판 프로젝트 수 제한도 로컬에서 동작하므로, 우회가 불가능하지는 않습니다. 두 제한 모두 일반 사용자에게는 충분한 구매 유도 장치로 작동하며, 강력한 보호는 서버 검증(모델 B)이 필요합니다.

권장 조치:
- 배포본마다 `src/license.ts`의 `SECRET` 값을 변경하세요. SECRET이 다르면 이전 배포본에서 발급된 키는 새 배포본에서 작동하지 않습니다.
- 강한 복제 방지가 필요하다면 **모델 B(서버 검증)** 로 전환을 검토하세요.

## 3. 배포 방법 (택1)

### (a) 비공개 GitHub 레포 접근권 판매

GitHub 비공개 레포에 소스를 올리고, 구매한 고객을 Collaborator로 초대합니다. 가장 간단하며 업데이트 배포도 쉽습니다.

### (b) 소스 ZIP 배포

프로젝트 폴더를 ZIP으로 압축해 고객에게 전달합니다. 업데이트 시 새 ZIP을 재전달해야 합니다.

### (c) npm pack / 사내 레지스트리

`npm pack` 으로 `.tgz` 패키지를 생성하거나 사내 npm 레지스트리에 배포합니다. 팀 내부 배포나 기업 환경에 적합합니다.

### (d) 단일 실행파일 번들링 (고급)

`pkg`, `nexe` 등의 도구로 Node.js를 포함한 단일 실행파일로 만들면 고객이 Node.js를 별도로 설치하지 않아도 됩니다. 설정이 복잡하므로 배포 규모가 클 때 검토하세요.

## 4. 고객 지원 체크리스트

고객 문의가 왔을 때 아래 5가지를 먼저 확인하세요. 이 조건이 모두 충족되면 대부분의 문제가 해결됩니다.

- [ ] Node.js 20 이상 설치됨
- [ ] cloudflared 설치됨
- [ ] `claude` 명령이 로그인된 상태로 작동함 (`claude --version` 으로 확인)
- [ ] 라이선스 키가 올바르게 전달됨 (`CPMC-XXXXXX-YY` 형식)
- [ ] `license.txt`에 키가 입력됐거나 `LICENSE_KEY` 환경변수로 지정됨

## 5. 가격 및 수익화

### 비용 구조

- **운영자(판매자) 비용:** 0원. 릴레이, 미리보기 서빙이 고객 PC에서 실행되므로 서버비 없음. cloudflared 퀵 터널은 무료.
- **AI 사용 비용:** 고객 본인의 Claude Code 계정으로 실행되므로 고객 부담.

### 수익화 모델

| 방식 | 설명 |
|------|------|
| **일회성 라이선스** | 키 1개당 고정 금액. 가장 단순. |
| **기간제 라이선스** | 만료일을 키에 포함하려면 `src/license.ts`의 라이선스 스킴 확장이 필요합니다. 현재 구현에는 만료 기능이 없습니다. |

## 6. 모델 B 로드맵 (다음 단계)

모델 A의 한계를 극복하고 진정한 SaaS로 전환하려면 아래 구성이 필요합니다.

- **중계 서버 클라우드 호스팅** — 판매자가 운영하는 서버에서 릴레이 상시 운영
- **미리보기 프록시 또는 영구 배포** — 고객이 오프라인이어도 접근 가능한 미리보기 URL
- **계정 및 구독 결제** — 사용자 인증, 구독 플랜, 결제 처리

관련 설계 문서: `docs/superpowers/specs` 및 `docs/superpowers/plans` 참고.
