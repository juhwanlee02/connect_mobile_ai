# 사용자 인수 가이드 — 앱 팩토리 7단계 파이프라인 (폰으로 풀사이클 실행)

> 이 문서는 **사용자(구매자)가 자기 폰으로 직접** 아이디어 → PRD → 목업 → 산정 → 개발 → 테스트 →
> 릴리즈까지 7단계를 한 번 완주해보는 인수 테스트 체크리스트다. 이 문서 자체로 "합격/불합격"을
> 판정하지는 않는다 — 실제 인수 판정은 사용자가 실기기로 이 순서를 따라가며 각 단계 산출물이
> 기대와 맞는지 확인하는 것으로 이뤄진다. 개발자 쪽 자동 검증(스킬 문서 대조·실 `claude -p` 스모크)
> 결과는 `.superpowers/sdd/task-7-report.md`를 참조.

## 0. 사전 준비 체크리스트

아래 항목을 실행 전에 전부 확인한다. 하나라도 빠지면 특정 단계에서 막힌다(어느 단계인지 표에 표시).

| 항목 | 확인 방법 | 없으면 영향받는 단계 |
|---|---|---|
| Node.js 20+ | `node --version` | 전체(서버 자체가 안 뜸) |
| `npm install` 완료 | 리포 루트에서 1회 실행 | 전체 |
| cloudflared | `cloudflared --version` | 전체(폰-PC 터널 연결) |
| Claude Code 로그인 | 터미널에서 `claude` 명령이 동작 | 전체(각 단계가 headless `claude -p`로 실행됨) |
| **Flutter SDK** (`flutter --version`, 3.x 이상) | 터미널에서 확인 | 5단계(개발) · 6단계(테스트) — 없으면 `flutter create`/`flutter build web`부터 실패 |
| Xcode + iOS 시뮬레이터 (macOS 전용) | `xcrun simctl list devices` 성공 | 5단계 게이트 ④(iOS 네이티브 스모크) · 7단계 스크린샷 캡처 — **없으면 해당 항목은 자동으로 "보류"로 표기되고 나머지는 정상 진행**(치명적 실패 아님) |
| GitHub CLI 인증(`gh auth status` 성공) | 터미널에서 확인 | 7단계 개인정보처리방침 발행 — 없으면 "보류: `gh auth login` 필요"로 표기, 나머지 릴리즈 산출물은 정상 진행 |
| (선택) 라이선스 키 | `license.txt` 또는 `LICENSE_KEY` 환경변수 | 없으면 체험판(프로젝트 1개 제한)으로 동작 |

> **PC 프로그램 재시작 시 재로그인 필요**: `npm start`를 다시 시작하면 터널 주소가 새로 발급된다.
> 아이디·비밀번호 자체는 `.relay-auth.json`에 저장돼 그대로 유지되지만, 자동 로그인용
> `phoneToken`은 폰 브라우저의 `localStorage`에 **주소(origin) 단위**로 저장되므로 새 주소에서는
> 이전 저장값이 무의미해진다 — 새 주소에서 **첫 1회만 다시 로그인**하면 된다(같은 실행 중 순단
> 재접속은 자동으로 계속 동작). 이는 브라우저 저장소 구조상의 알려진 한계이며 기대 동작이다.

> **필수 후속(이 문서만으로는 검증 안 됨)**: 7단계 release의 ④스크린샷(iOS 시뮬레이터 캡처)·
> ⑤개인정보처리방침 발행(GitHub Pages)은 macOS+Xcode 시뮬레이터+`gh auth login` 환경이 있어야
> 라이브로 확인된다. 이 환경이 준비되면 사용자 인수 전에 `/pipeline-release`를 실제로 1회
> 완주해 두 항목이 "보류"가 아니라 정상 산출물로 나오는지 반드시 확인할 것.

실행:
```bash
npm start
```
터미널에 아래 형태의 **공유 카드**가 뜬다.
```
✅ 준비 완료! 폰에서 아래로 접속하세요

  주소:    https://xxxx-xxxx.trycloudflare.com
  아이디:   admin
  비밀번호: gT7kpQ
  ── 또는 이 링크 하나만 폰에서 열기(아이디 자동 입력) ──
  링크:    https://xxxx-xxxx.trycloudflare.com/#id=admin
```
이 터미널 창은 세션 내내 열어둔다(닫으면 연결이 끊긴다).

**폰 로그인**: 폰 브라우저에서 카드의 **링크**를 열면(또는 주소만 열고 아이디를 직접 입력) 아이디가
자동 입력된다 → 비밀번호 입력 후 **로그인**. 로그인되면 상단에 "PC 연결됨" 배지와 프로젝트 바가
보인다. 같은 실행 중에는 탭을 닫았다 다시 열어도 로그인 화면 없이 자동으로 홈으로 들어간다(아래
"로그인 시나리오" 참조).

**파이프라인 프로젝트 생성**: 프로젝트 바의 **➕ 새 프로젝트** 탭 → 이름 입력(영문/숫자) →
"파이프라인 앱으로 만들까요?"에서 **예**를 선택(취소하면 구식 "빠른 웹앱" 모드로 만들어져 7단계
파이프라인이 시작되지 않는다 — 반드시 예를 선택할 것).

**단계 자동 전개 규칙(알아두면 헷갈리지 않음)**: 1단계(아이디어)만 사용자가 채팅으로 아이디어를
입력해야 시작된다. 2단계(PRD)부터는 이전 단계를 **컨펌하는 순간 다음 단계가 자동으로 실행**된다
(별도로 "시작해줘"라고 보낼 필요 없음) — 몇 초~몇 분 후 새 단계 카드가 "진행 중"으로 바뀐다.

## 0-1. 로그인·자동 로그인 인수 시나리오

파이프라인 7단계를 시작하기 전에, 아이디/비밀번호 로그인과 자동 로그인이 기대대로 동작하는지
먼저 확인한다. `npm start`로 공유 카드가 뜬 상태에서 아래 4개를 순서대로 확인한다.

- [ ] **① 링크로 접속 → 아이디 자동 입력 → 로그인 성공**: 폰 브라우저에서 공유 카드의 **링크**
  (`.../#id=<아이디>`)를 연다. 기대 결과: 로그인 화면의 아이디 칸에 카드의 아이디가 이미 채워져
  있다. 비밀번호를 입력하고 **로그인**을 누르면 성공해 상단에 "PC 연결됨" 배지와 프로젝트 바가
  뜬다.
- [ ] **② 탭 닫고 재방문 → 로그인 화면 없이 홈**: ①로 로그인에 성공한 뒤, 폰 브라우저 탭을 닫았다
  같은 주소로 다시 연다(주소는 그대로, PC 프로그램도 계속 켜진 상태). 기대 결과: 로그인 화면이
  뜨지 않고 저장된 `phoneToken`으로 조용히 재접속되어 바로 홈(프로젝트 바)이 보인다.
- [ ] **③ 비밀번호 오입력 → 오류 문구**: 로그인 화면에서 카드에 나온 아이디는 그대로 두고
  비밀번호만 일부러 틀리게 입력해 **로그인**을 누른다. 기대 결과: **"아이디 또는 비밀번호가
  올바르지 않아요"** 문구가 뜨고 로그인되지 않는다(로그인 화면에 남아 있음).
- [ ] **④ PC 재시작 후 새 주소 → 1회 재로그인(기대 동작)**: PC 터미널에서 `Ctrl+C`로 종료 후
  `npm start`를 다시 실행해 **새 주소**로 카드를 받는다. 그 새 주소로 폰에서 접속한다. 기대
  결과: 이전 주소에서 로그인해 저장해 둔 `phoneToken`은 새 주소(origin)에서는 적용되지 않으므로
  로그인 화면이 다시 뜬다 — **이것은 결함이 아니라 기대 동작**이다(브라우저 저장소가 주소 단위로
  분리되기 때문). 카드의 아이디·비밀번호로 다시 로그인하면(①과 동일) 성공하고, 이후 같은 주소
  안에서는 다시 ②처럼 자동 로그인된다.

전부 통과하면 로그인·자동 로그인 기능은 인수 완료로 본다. ③에서 다른 문구가 뜨거나, ①·②·④에서
로그인이 되지 않으면 해당 단계 번호를 기록해 개발 태스크로 돌아가 확인한다.

## 1단계 — 아이디어 발굴 (`ideation`)

- **폰에서 보이는 것**: 채팅 입력창. 프로젝트를 만들면 바로 이 단계 카드가 "대기" 상태로 보인다.
- **사용자가 할 일**: 채팅에 만들고 싶은 앱을 자유 문장으로 입력(예: "물 마시기 리마인더 앱 만들고
  싶어") — 또는 "제안해줘"라고 보내면 시장 리서치로 후보 3~5개를 카드로 제안받는다.
- **기대 산출물**: `IDEAS.md`(전문 보기) + 후보 카드(HTML, 목업 뷰어로 열람). 리서치 모드면 카드마다
  근거 URL·opportunity_score가 붙는다.
- **컨펌 포인트**: 카드가 여러 장이면 채팅으로 `<slug> 선택`을 보내 하나를 고른 뒤 **컨펌** 버튼.
  카드가 1장(직접 입력 모드)이면 바로 컨펌 가능.
- **흔한 문제**:
  - 8초 안에 서버 응답(ack)이 없으면 "다시 전송" 버튼이 뜬다 — 눌러서 재전송.
  - 리서치 모드가 오래 걸리면(웹 검색 다수) 인내심 있게 기다린다(다른 단계보다 느릴 수 있음).
- **재시도/롤백**: 이 단계는 첫 단계라 롤백 대상이 없다. 마음에 안 들면 채팅으로 "다른 아이디어로
  다시 제안해줘" 등 피드백을 보내면 카드가 갱신된다.

## 2단계 — PRD 확정 (`prd`)

- **폰에서 보이는 것**: 카드가 자동으로 "진행 중"으로 전환 → 완료되면 요약 카드(앱 이름·MUST
  기능·화면 목록·백엔드 예비 판정) + [PRD 전문 보기] 버튼(마크다운 뷰어).
- **사용자가 할 일**: 전문을 읽고, 고칠 부분이 있으면 채팅 피드백("§3에 알림 기능 추가해줘" 등).
  질문에 답해야 진행되는 경우도 있다(최대 2~3개, 예: "타겟 사용자가 누구인가요?") — 답하면 이어서
  작성된다.
- **기대 산출물**: `docs/PRD.md`(메타 + §1~§10, 화면 ID·applicationId 확정 — 이후 되돌리기 어려운
  값이므로 여기서 꼼꼼히 확인).
- **흔한 문제**: applicationId가 `com.example`이면 결함(발생하면 안 됨) — 프로젝트명 기반 값인지
  확인. 화면 ID가 영문 kebab-case인지 확인(한글·대문자면 이후 단계에서 문제).
- **재시도/롤백**: 컨펌 전에는 몇 번이든 피드백으로 수정 가능. 컨펌 후 문제를 발견했으면 단계
  스텝퍼에서 "PRD" 탭 → 확인 대화상자("기존 산출물은 history/에 보관됩니다") → 롤백해 다시 진행.

## 3단계 — UI/UX 목업 (`mockup`)

- **폰에서 보이는 것**: 완료되면 [목업 열기] 버튼 — 탭하면 뷰어가 iPhone/Android/꽉 채움 프레임
  전환 칩과 함께 정적 HTML 목업을 그대로 폰 화면에서 넘겨볼 수 있다.
- **사용자가 할 일**: 화면을 하나씩 넘겨보며(실제 링크로 이동 가능) 레이아웃·문구·흐름을 확인.
  마음에 안 들면 "home 화면 버튼 색을 파란색으로" 같은 화면 단위 피드백.
- **기대 산출물**: `mockup/index.html`(목차) + `mockup/<화면ID>.html`(PRD §4 화면 수와 정확히 일치).
- **흔한 문제**: PRD에 없는 새 화면을 요구하면 목업이 바뀌지 않고 "PRD 변경입니다 — 되돌리기를
  권합니다"라는 안내만 온다 — 새 화면이 필요하면 2단계로 롤백해 PRD부터 고쳐야 한다.
- **재시도/롤백**: 특정 화면만 재생성되므로 여러 번 피드백을 보내도 다른 화면은 그대로 유지된다.

## 4단계 — 비용·기술 산정 (`estimate`)

- **폰에서 보이는 것**: 완료되면 백엔드 판정(로컬/정적/백엔드+스택) + MAU 시나리오별 예상 월 비용
  카드. 백엔드 미채택이면 "로컬 완결형, 서버 운영비 없음"이라고만 뜬다.
- **사용자가 할 일**: 기능을 더 넣거나 뺄 수 있는 마지막 저비용 시점 — "이 기능은 빼줘" 등으로
  조정하면 **PRD도 함께 갱신**되고 diff 요약이 표시된다. 이 단계 컨펌은 "갱신된 PRD 재승인"이라는
  뜻이므로 diff를 꼭 확인.
- **기대 산출물**: `ESTIMATE.md`(§1 백엔드 결정 + §7 PRD diff 요약).
- **흔한 문제**: 조정으로 화면 목록이 바뀌면(화면 추가/삭제) "목업 롤백을 권장합니다"라는 문구가
  같이 온다 — 이 경우 3단계로 롤백해 영향받은 화면만 다시 만드는 게 정상 흐름이다.
- **재시도/롤백**: 조정 회차는 계속 늘어날 수 있음(1→2→3…) — 몇 번이든 반복 가능.

## 5단계 — 개발 (`develop`) — **가장 오래 걸리는 단계**

- **폰에서 보이는 것**: `flutter create` → 스타터 오버레이 적용 → 화면 구현 → 게이트 통과까지
  진행 상황이 채팅에 **단계별로 한 줄씩** 스트리밍된다(①~⑨ 순서, 예: "① 입력 확인 완료 — PRD
  화면 2개…", "④ 화면 구현 완료 — home, counter", "⑦ 게이트 통과 — analyze 0, test 통과…"). 완료
  되기까지 **수 분~수십 분**(화면 수·백엔드/광고 채택 여부에 따라 다름 — 스모크 기준 참고치는 아래
  "실측 참고" 참조) 걸릴 수 있으니 채팅이 잠시 멈춰도 정상이다.
- **사용자가 할 일**: 완료 보고(구현 화면 목록·게이트 4종 결과)를 확인하고 컨펌. 이 단계는 폰에서
  직접 조작해볼 수 없다(코드만 생성됨 — 실제 조작은 6단계 미리보기에서).
- **기대 산출물**: `app/`(Flutter 프로젝트) — `pipeline.json`의 `artifacts.app`에 등록.
- **흔한 문제**:
  - 게이트(analyze/test/appRoutes 대조) 중 하나라도 실패하면 완료로 표시되지 않고
    "피드백 중" 상태로 남는다 — 채팅에 실패 사유가 요약되니 읽어보고 "다시 시도해줘"로 재실행하거나
    그대로 기다리면 자동으로 재시도되지 않으니 피드백을 보내야 한다.
  - **iOS 네이티브 스모크(게이트 ④)는 macOS+Xcode 시뮬레이터가 없으면 자동으로 생략**되고 그
    사실이 보고에 명시된다 — 실패가 아니라 "생략"이므로 다른 3개 게이트만 통과하면 정상 진행.
  - PRD에 없는 새 기능을 요청하면 코드가 바뀌지 않고 "PRD 변경입니다" 안내만 온다.
- **재시도/롤백**: 버그·스타일 수정 피드백은 이 단계 안에서 게이트 4종을 전부 재실행한 뒤 다시
  완료 표시된다. 큰 폭의 재설계가 필요하면 4단계(산정)나 3단계(목업)로 롤백.

## 6단계 — 테스트 (웹 미리보기, `test`)

- **폰에서 보이는 것**: 완료되면 [미리보기 열기] 버튼 — 실제 웹 빌드 결과를 폰 화면 프레임 안에서
  **직접 탭하며 조작**할 수 있다(이 파이프라인에서 유일하게 실제 동작을 만져볼 수 있는 단계).
- **사용자가 할 일**: 화면을 눌러보며 버그·오탈자·레이아웃 확인. 채팅 보고에 "web에서 검증 불가
  목록"(광고·푸시·인앱결제·PRD §10 네이티브 요건 — 전부 "실기기에서만 확인 가능")이 함께 오니,
  이 항목들은 여기서 확인 안 돼도 정상이라는 걸 알아둔다.
- **기대 산출물**: `preview/`(웹 빌드 사본).
- **흔한 문제**: 기능 추가 요청은 이 단계에서 처리되지 않고 "PRD 변경입니다" 안내만 온다(버그·문구·
  스타일 수정은 이 단계에서 바로바로 재빌드됨).
- **재시도/롤백**: 버그 수정 피드백 → 재빌드 → 미리보기 갱신, 몇 번이든 반복 가능.

## 7단계 — 릴리즈 패키지 (`release`)

- **폰에서 보이는 것**: 완료되면 스토어 제출용 산출물 요약(제목·설명 글자수, 아이콘 생성 방식,
  §8 체크리스트 미체크 항목과 사유, 스크린샷 캡처 결과, 개인정보처리방침 발행 결과)이 채팅으로
  보고되고 [RELEASE.md 전문 보기] 버튼이 생긴다.
- **사용자가 할 일**: §8 최종 체크리스트의 **미체크 항목**을 먼저 확인 — 흔한 미체크 사유:
  - "광고 실 ID 교체 필요"(광고 채택 시 — 테스트 ID를 실제 AdMob 유닛 ID로 교체해야 함)
  - "아이콘 임시(스타터 플레이스홀더) — 교체 필요"(Chromium 렌더가 실패한 환경)
  - "스크린샷 보류(Phase 5에서 활성화 — 비macOS 환경)" — **macOS가 아니면 정상적으로 이 상태로
    남는다**(치명적 결함 아님, 스크린샷은 macOS+Xcode 시뮬레이터 환경에서만 자동 캡처된다)
  - "개인정보처리방침 보류: `gh auth login` 필요" 또는 "공개용 문의 이메일 미확정" — 채팅으로
    `/pipeline-release 피드백: 문의 이메일은 <실제 이메일>입니다`처럼 답을 주면 재시도된다
- **기대 산출물**: `release/`(RELEASE.md + `icons/`·`graphics/`·`screenshots/`·`privacy.html`).
- **컨펌하면**: host가 파이프라인을 `done`으로 처리한다 — 이후는 아래 "8. 완료 후" 절차.
- **흔한 문제**: 스크린샷·개인정보처리방침이 "보류"로 남아 있어도 **릴리즈 전체가 막히지는
  않는다** — 나머지 텍스트·아이콘 산출물은 그대로 컨펌 가능하고, 보류 항목은 사전 준비(Xcode
  시뮬레이터, `gh auth login`, 문의 이메일)를 채운 뒤 `/pipeline-release 피드백: ...`으로 재시도하면
  된다.
- **재시도/롤백**: 스토어 문구·아이콘·스크린샷 헤드라인·개인정보처리방침 각각 개별 재시도 가능
  (전체 재생성이 아니라 해당 부분만).

## 8. 완료 후 — 스토어 콘솔에 복붙하는 순서

`release/RELEASE.md`를 열어(폰 뷰어 또는 PC에서 직접) 위에서 아래 순서로:

1. **§8 최종 체크리스트를 먼저 전부 해결**한다(미해결 항목이 있으면 실제 제출 전에 반드시 처리 —
   특히 광고 실 ID 교체는 자동화되지 않는 수동 작업이다).

3. **App Store Connect**: §1 표의 앱 이름·부제·설명·키워드·스크린샷·아이콘(1024)을 행 순서 그대로
   복붙/업로드. §3-1 앱 개인정보 설문 답변을 그대로 입력. 아이콘 1024가 colorType=6(알파 채널

4. **개인정보처리방침 URL**: §4에 발행 완료 URL이 있으면 두 콘솔의 "개인정보처리방침" 입력란에
   그대로 붙여넣는다. "보류"라면 §8을 먼저 해결.
5. 두 콘솔 모두 내부 테스트 트랙에 먼저 업로드해 실기기로 광고·푸시·인앱결제 등 웹에서 검증 못한
   항목(6단계에서 안내된 목록)을 최종 확인한 뒤 정식 심사 제출.

## 9. Part A 라이브 스모크에서 관측된 실제 동작·한계 (참고)

이 절은 개발 환경(macOS, Flutter 3.35.1, Xcode 시뮬레이터, `gh` 미인증)에서 5단계(개발) 스킬을
실 `claude -p`로 1회 완주시켜본 결과를 반영한다(전체 표는 `.superpowers/sdd/task-7-report.md`).

- 5단계는 정말 다른 단계보다 훨씬 오래 걸린다 — `flutter create` + 스타터 오버레이 적용(`pub get`
  포함) + 화면 2개 구현 + 게이트 4종(analyze/test/appRoutes 대조/iOS 시뮬레이터 빌드)까지 실측
  **약 7.4분**(444초, 54턴, 화면 2개짜리 초미니 앱 기준) 소요 — 스펙 §8의 60분 타임아웃 상한 안에서
  여유 있게 완주. 화면 수·백엔드·광고 채택 여부에 따라 실제 사용자 프로젝트는 이보다 더 걸린다.
- `cd app && <명령>` 후 별도 호출로 `cd ..` 복귀하는 절차(Phase 5 Task 4에서 도입)가 실제로도
  문제없이 동작해 이후 명령이 프로젝트 루트 기준으로 정확히 실행됨을 확인(권한 거부 0건).
- PRD §4 화면 ID(`home`, `counter`)가 `app/lib/router.dart`의 `appRoutes`에 정확히 반영되고
  (`['home', 'counter', 'settings']`), 1:1 대조 게이트가 통과함을 확인 — `settings`는 스타터 기본
  화면(PRD 외)으로 규정된 유일한 예외로 처리됨.
- iOS 시뮬레이터 스모크(게이트 ④)는 macOS+Xcode 환경에서 **PASS**(`flutter build ios
  --simulator --debug` 성공) — 이 환경이 없는 사용자는 이 항목이 자동으로 생략되고 나머지 3개
  게이트만으로 진행되는 것이 정상 동작이다.
- 발견된 문서/설정 결함: **없음** — 스킬 문서 수정 없이 전 게이트 통과·상태 전이(`starting` →
  `awaiting_confirm`)·`artifacts.app` 등록이 정상 동작했다.

## 10. 파이프라인 커스터마이징(곁가지 템플릿) 인수 시나리오

7단계 기본 파이프라인 인수(위 1~8절)와 별개로, **템플릿 편집** 기능을 폰으로
직접 확인하는 체크리스트다. `npm start` 후 폰(또는 PC 브라우저)에서 접속해 아래 순서대로
진행한다.

- [ ] **① 템플릿 복제**: 홈 → **[⚙️ 템플릿]** → 기본 템플릿 **[복제]** → 이름 입력.
  기대 결과: 목록에 내 템플릿(곁가지)이 새로 생긴다(기본 템플릿은 그대로 남아 있음).
- [ ] **② 스텝 추가/순서변경/삭제**: 방금 만든 템플릿의 **[스텝 편집]** → **＋ 스텝 추가**로
  "경쟁사 분석" 입력.
  기대 결과: 스텝 목록에 "경쟁사 분석"이 나타나고, **↑↓**로 순서 이동·**✕**로 삭제가 정상
  동작한다.
- [ ] **③ 프롬프트 편집/복원**: 스텝의 **✏️ 프롬프트**를 열어 내용을 수정·저장.
  기대 결과: 화면을 나갔다 다시 열어도 수정 내용이 유지된다. builtin(기본) 스텝의 프롬프트를
  고치면 **✏️** 표시가 붙고, **[기본값 복원]** 버튼으로 원래 문구로 되돌릴 수 있다.
- [ ] **④ 커스텀 템플릿으로 프로젝트 생성**: **[＋ 새 프로젝트]** → 파이프라인 → 템플릿 번호에서
  방금 만든 템플릿 선택.
  기대 결과: 프로젝트 화면의 스텝 바가 기본 7단계가 아니라 방금 편집한 커스텀 구성(스텝
  추가/순서변경 반영)으로 표시된다.
- [ ] **⑤ 기존 프로젝트 회귀 확인**: 이 기능 이전에 만든(또는 기본 템플릿으로 만든) 7단계
  프로젝트를 연다.
  기대 결과: v1 스냅샷이 정상 승격되어 여전히 7단계 스텝 바로 정상 표시된다(기존 진행 상황이
  깨지지 않음).

전부 통과하면 곁가지 템플릿 기능은 인수 완료로 본다. 실패 항목이 있으면 어느 단계에서
막혔는지 기록해 해당 기능 개발 태스크로 돌아가 확인한다.

## 11. 설정 페이지(관리 UI) 인수 시나리오

PC 브라우저에서 여는 `/setup` 관리 페이지가 스펙대로 동작하는지 확인하는 체크리스트다. 아래
순서로 진행한다.

- [ ] **① 첫 실행 → 설정 페이지 자동 오픈**: `.relay-auth.json`이 없는 상태(최초 실행 또는
  파일을 지운 뒤)에서 `npm start`를 실행한다. 기대 결과: 준비되면 PC 기본 브라우저에 설정
  페이지가 **자동으로 열리고**, 터미널 카드에는 항상 `관리: http://localhost:<포트>/setup?k=<키>`
  줄이 표시된다. 이미 자격증명 파일이 있는 상태로 재실행하면 자동으로는 열리지 않고(카드의
  `관리:` 주소로 수동으로 열어야 함) 이 부분도 함께 확인한다.
- [ ] **② 계정 생성/변경**: 설정 페이지 **계정** 탭에서 아이디/비밀번호를 원하는 값으로 입력해
  **저장**한다. 기대 결과: 저장 직후에는 폰의 기존 자동 로그인 세션이 그대로 유지되고, **다음
  로그인부터** 새 아이디/비밀번호가 적용된다(즉시 로그아웃되지 않음).
- [ ] **③ QR 스캔 → 폰 로그인**: 설정 페이지 상단 **📱 폰 접속** 카드의 QR 코드를 폰 카메라로
  스캔한다. 기대 결과: 아이디가 이미 입력된 상태로 로그인 화면이 열리고, 비밀번호만 입력하면
  로그인에 성공한다.
- [ ] **④ 산출물 템플릿 수정 → 새 프로젝트에 반영·기존 프로젝트 무영향**: **산출물 템플릿** 탭에서
  파일 하나(예: `PRD.template.md`)를 열어 내용을 눈에 띄게 수정하고 저장한다. 기대 결과: 저장
  **이후 새로 만드는** 파이프라인 프로젝트에는 수정된 서식이 반영되고, 저장 **이전에 이미 만든**
  프로젝트의 산출물에는 영향이 없다(재생성해도 원래 서식 기준으로 만들어진 결과가 바뀌지 않음).
- [ ] **⑤ 복원 동작**: 방금 수정한 파일에서 **[원본으로 복원]** 버튼을 누른다. 기대 결과: 파일
  내용이 수정 전 원본으로 되돌아가고(최초 저장 시 자동 백업된 `templates/.orig/` 사본에서 복원),
  이후 새 프로젝트는 다시 원래 서식으로 생성된다.
- [ ] **⑥ 비-loopback·틀린 키 접근 차단**: 폰(또는 다른 PC)에서 터널 주소로 `/setup`을 열어본다.
  기대 결과: 페이지 존재 자체가 드러나지 않고 접속이 거부된다(404). 이어서 PC 브라우저에서
  `?k=` 값을 임의로 틀리게 바꿔 `/setup`을 연다. 기대 결과: "관리키가 올바르지 않아요"류 오류로
  거부된다(401) — 두 경우 모두 정상 설정 화면이 노출되지 않아야 한다.

전부 통과하면 설정 페이지(관리 UI) 기능은 인수 완료로 본다. 실패 항목이 있으면 어느 번호에서
막혔는지 기록해 해당 기능 개발 태스크로 돌아가 확인한다.

## 12. 산출물 md 직접 수정·접이식 진행 헤더 인수 시나리오

폰에서 산출물 문서를 직접 고쳐 저장하는 기능과, 상단 진행 표시가 한 줄로 접히는 기능을 확인하는
체크리스트다. 진행 중인 파이프라인 프로젝트(예: 2단계 PRD 완료 직후, `awaiting_confirm` 상태)에서
아래 순서로 진행한다.

- [ ] **① md 편집 → 저장 → 뷰어 갱신 → 컨펌 정상**: 완료된 산출물(예: `docs/PRD.md`)의 뷰어를 열고
  **[✏️ 직접 수정]** → 내용을 눈에 띄게 한 줄 고침 → **[저장]**. 기대 결과: 저장 직후 뷰어가
  수정한 내용으로 즉시 갱신되고, 채팅에 "사용자가 문서를 직접 수정했어요" 로그가 남는다. 이어서
  **[✓ 컨펌]**을 누르면 평소와 동일하게 다음 단계로 정상 진행된다(수정본 기준으로).
- [ ] **② Claude 실행 중 편집 시 거부 안내**: 다음 단계가 "진행 중" 상태일 때(또는 채팅으로 피드백을
  보내 스킬이 실행되는 동안) 같은 프로젝트의 산출물을 **[✏️ 직접 수정]** → 내용 수정 → **[저장]**을
  시도한다. 기대 결과: 저장이 거부되고 "Claude가 파일을 쓰는 중이니 끝난 뒤 수정해 달라"는 안내가
  뜬다 — 편집 중이던 내용은 지워지지 않고 textarea에 그대로 남아 있어야 한다. 진행이 끝난 뒤 같은
  내용으로 다시 **[저장]**하면 ①처럼 정상 저장된다.
- [ ] **③ 진행 헤더 접힘 유지(재접속 후에도)**: 상단 진행 표시 줄을 탭해 펼친 뒤, 다시 탭해
  접는다(또는 반대로 펼친 채로 둔다). 폰 브라우저 탭을 닫았다 같은 주소로 다시 열어(로그인은
  자동으로 유지됨) 같은 프로젝트를 연다. 기대 결과: 직전에 남겨둔 접힘/펼침 상태가 그대로
  유지된다(자동으로 펼쳐지거나 접히지 않음) — 프로젝트별로 기억된다.
- [ ] **④ 아이디에이션 산출물의 감사 로그 위치**: 1단계(아이디어 발굴)를 완료한 프로젝트의
  `IDEAS.md`를 뷰어로 연다. 기대 결과: 후보 카드 목록·선택 안내에는 카드 내용(컨셉·타겟·기능
  등)만 보이고, 검색 횟수·후보 풀 크기 같은 실행 통계 숫자는 문서 최하단의 "자세히(만든 과정
  기록)" 섹션에 모여 있다. 완료 시 채팅 보고에도 그런 통계 숫자가 나열되지 않고 카드 요약
  위주로 온다.

전부 통과하면 md 직접 수정·접이식 진행 헤더 기능은 인수 완료로 본다. 실패 항목이 있으면 어느
번호에서 막혔는지 기록해 해당 기능 개발 태스크로 돌아가 확인한다.
